# aiogram 3.x · пример FSM-сценария from aiogram import Router, F from aiogram.fsm.context import FSMContext from states import FocusFlow from services.notifications import silence router = Router() @router.message(F.text == "/focus") async def cmd_focus(message: Message, state: FSMContext): await state.set_state(FocusFlow.duration) await message.answer("На сколько глушим? Ответь числом минут.") @router.message(FocusFlow.duration) async def got_duration(message: Message, state: FSMContext): minutes = int(message.text) await silence(user_id=message.from_user.id, minutes=minutes) await state.clear() await message.answer(f"Готово. Включу обратно через {minutes} мин.")
// 03 — Подход

Как устроена работа.

Четыре шага. Никаких длинных брифов, презентаций на 40 слайдов и созвонов на полтора часа.

шаг 01

Слушаю

Созвон на 30 минут. Фиксирую боль, сценарии и метрику успеха. Если задача не для бота — говорю прямо.

шаг 02

Проектирую

Карта сообщений, FSM-сценарии, схема данных. Показываю до кода — правки дешевле на бумаге.

шаг 03

Собираю

Итерации раз в неделю. Демо в личку, доступ к тестовому боту. Без NDA-пауз на «внезапный аудит».

шаг 04

Поддерживаю

Аптайм, мониторинг, апдейты под новые версии Bot API. Не бросаю на следующий день после релиза.

// 04 — Принципы

Хороший бот — это невидимый бот.

Если пользователь замечает, что общается с ботом — что-то пошло не так. Я стараюсь делать так, чтобы бот решал задачу и не мешал жить.

01

Не шумлю

Никаких рассылок «по базе» и мотивационных цитат по понедельникам. Если бот пишет — это потому что у него есть что сказать.

02

Понятный с первого сообщения

Онбординг за три экрана. Никаких «введите /start для начала» — кнопки и подсказки сразу.

03

Не притворяюсь человеком

Если задача требует диалога с живым человеком — передаю человеку. Бот не должен имитировать эмпатию.

04

Работает офлайн

Аптайм ≥99.5%. Если что-то ломается — пользователь узнает не из сообщения «ой, что-то пошло не так», а из тихо восстановленной работы.
